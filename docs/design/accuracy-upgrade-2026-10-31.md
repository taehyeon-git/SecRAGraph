# SAST 흐름·DAST 정확도 개선 설계

## 목표

현재 고정 회귀 사례의 Opengrep FP 1건·FN 1건과 숫자형 SQL 주입 DAST FN 1건을 재현해 줄인다. 업로드 소스의 파일 간 흐름은 기존 Opengrep 파일 내부 분석과 별도로 검증 가능한 Python 정적 import 경로부터 지원한다. 세 결과는 각각 정상 대조 사례와 실제 실행 증거로 확인하며 임의 프로젝트의 완전한 탐지율로 표현하지 않는다.

## 경계와 선택

- Opengrep 1.32.0을 유지한다. 공식 파일 간 모드는 현재 테스트용 사전 공개판이므로 배포 스캐너로 바꾸지 않는다. 별도 `python-flow` SAST가 검증된 스냅샷의 Python 파일만 AST로 파싱하고 정적인 로컬 import·함수 호출을 추적한다. 소스를 import하거나 실행하지 않는다.
- `python-flow`는 파일 간 데이터 경로가 입증된 경우만 `PYFLOW/SHELL` 또는 `PYFLOW/SQL` finding을 생성한다. source·중간 호출·sink의 파일과 줄을 기록하고 원문은 보관하지 않는다. 동적 import, 런타임 다형성, 지원하지 않는 구문·시간 한도는 완료한 검사로 위장하지 않고 범위 경고/partial로 기록한다.
- SQL f-string 누락은 출처·해시를 보존한 vendored Opengrep 규칙 수정으로 해결한다. shell 규칙의 넓은 탐지 범위는 유지하고, 숫자 변환이 같은 직선 코드 블록에서 확실히 확인된 발견만 AST로 보수적으로 제외한다. 분기·재할당·이름 가리기 등 불확실한 경우는 경고를 유지한다. 탐지 품질은 규칙별 정상·취약 사례와 고정 외부 도전의 전후 비교로 확인한다.
- ZAP이 놓친 숫자형 SQL 주입은 `ZAP/40018`으로 위조하지 않는다. 별도 격리 DAST 차등 검사를 추가한다. 승인된 일회용 컨테이너의 명시된 GET 시작 경로만 대상으로, 반복 기준 응답과 참/거짓 조건 응답의 안정적 차이를 요구한다. 원시 요청·응답·토큰은 저장하지 않는다. 탐지가 불확실하거나 검사가 불완전하면 음성 판정 대신 범위 경고를 낸다.
- 회원 업로드는 DAST·이미지 빌드·Git 이력 실행을 시작하지 않는다. CodeQL은 공개 저장소 자체 검사에만 사용한다.

## 검증

1. 기존 25개 스캐너 사례의 정확한 rule/file/line 라벨을 유지해 FP/FN 전후를 비교한다. 파일 간 흐름은 다중 파일 취약·정상 대조, import 별칭, 안전 변환, 파라미터화 SQL, 순환/미해석 import와 경로 제한을 별도로 시험한다.
2. DAST는 기존 8개 사례의 경로별 방문·공격형 요청 증거를 유지하고, 숫자형 취약·정상 대조를 새 규칙에 귀속한다. ZAP 원본 규칙의 결과와 추가 차등 규칙의 결과를 분리해 기록한다.
3. REST/CLI/Markdown/SARIF의 engine·rule·trace·실행 범위가 같은 보고서에서 일관적인지 확인한다. 실제 Docker와 CI의 회귀 벤치마크를 통과한 결과만 README에 반영한다.

## 한계 표현

지원한 정적 import·sink의 파일 간 추적은 Python 전체 의미 분석이 아니다. 동적 import, 반사, 복잡한 객체/프레임워크 흐름과 다른 언어의 파일 간 흐름은 별도 평가 대상이다. 작성자 회귀 코퍼스의 FP=0·FN=0이 실사용 무오류를 보장하지 않는다.
