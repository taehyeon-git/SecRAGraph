# Whole-tool pipeline benchmark

## Goal and boundaries

Measure SecRAGraph as a usable tool, from member authentication and upload through the shared LangGraph scan, persisted report and three renderings, while retaining separate evidence for the CI-only DAST, image/SBOM and Git-history tracks. Publish one run-linked benchmark bundle. Each track keeps its own denominator; there is no combined detection F1.

The member upload route can run SAST, secret, configuration and OSV dependency analysis. DAST, image scanning and Git-history scanning have different targets and trust boundaries. The scan graph's RAG enrichment can run only when a retriever is configured; the keyless Compose stack does not represent live LLM answer quality. The existing deterministic LangGraph/RAG corpus remains a separate contract track.

## Measurement

1. Extend the existing disposable Compose smoke stack with a fixed mixed ZIP and a second member. Record startup, login, upload, persisted JSON fetch, Markdown fetch and SARIF fetch times separately. Require authenticated access, owner isolation, exact persisted JSON equality, valid SARIF, report coverage records and no unredacted synthetic secret. Record `ScanExecution` status, eligible/scanned files and time by engine. Do not gate variable wall time on shared runners.
2. Keep OSV/CWE network calls out of the reproducible Compose score. Use a controlled application-level fixture with injected OSV/CWE/retriever ports to verify those graph edges, and label any external-provider quality unmeasured. The Compose benchmark must never imply a successful external lookup merely because a graph node ran.
3. Aggregate artifacts from the same CI run: member API benchmark, multi-engine authored regression, deterministic RAG graph evaluation, DAST synthetic API evaluation, image/SBOM validation and Git-history gate. The dependency audit is a status-only track taken from the successful upstream CI job, not a measured vulnerability count. The aggregate job runs only on trusted `main` push, schedule and manual events because component artifacts are published only there. PRs run the benchmark harness and aggregator fixture tests without publicly uploading a partially validated bundle. The job depends on all component jobs, so any failed upstream job prevents publication and fails the workflow. Validate each available source's schema, completion and provenance before publishing `pipeline-benchmark.json` and `.md`. Carry `GITHUB_RUN_ID`, `GITHUB_SHA` and each artifact SHA-256; compare source revisions when fields exist and report `unverified` when a component schema has no revision. Report counts and timings by track, not one pooled score. Missing or malformed evidence fails the aggregate job; no partial green summary.
4. Capture a pre-change baseline for the repeated-finding RAG enrichment path. The measured baseline is 20 identical-query findings, 20 retrieval calls and 219 ms wall time with a controlled 10 ms retriever delay. Because this confirms duplicate calls, improve it with per-invocation validated-result reuse, retaining per-finding reference merge, ordering, limit and deadline checks. Run the identical workload after the change and record call count and measured elapsed time. Do not claim CI time changes are causally attributable to this optimization.
5. The controlled graph contract exposed another gap: the RAG node iterated only deterministic scanner findings, so OSV findings added by the dependency audit never received retrieved citations. Extend enrichment to include these additions after deterministic findings, preserving the existing first-20 priority, deadline behavior and report order. Verify an OSV-only result and the mixed result both receive citations when a retriever is configured. This does not make external OSV or LLM output deterministic.

## Result interpretation

Authored cases are regression contracts, not a representative vulnerability sample. External OSV feeds, CVE state, Trivy DB and runner timing vary. The bundle must carry source revision, manifest hashes where available, runner/platform and a description of missing external truth labels. Counts for scanner, RAG and DAST cannot be pooled. All artifacts must omit credentials, raw upload contents and scanner raw HTTP traffic.
