# 위협 모델

범위는 로컬 CLI, 루프백 Compose API/Streamlit, PostgreSQL·Qdrant, 선택적 모델 제공자, GitHub Actions 정의입니다. 이 모델은 구현된 통제와 잔여 위험을 기록합니다. 공개 인터넷이나 여러 사용자에게 노출하는 운영 배포는 현재 범위 밖입니다.

## 자산과 공격자

보호할 자산은 업로드된 비공개 코드, 코드 안의 자격 증명, 생성된 보고서, `app` 스키마의 스캔·감사 메타데이터, `intel` 스키마의 CVE/CWE 데이터, Qdrant 문서 chunk, 모델·DB 자격 증명, CI 토큰입니다. 공격자는 업로드 파일/ZIP, 질문, 수집 문서, 저장 데이터, 모델 출력을 제어하거나 개발자의 로컬 호스트에 접근할 수 있다고 가정합니다. 기본 포트는 호스트 `127.0.0.1`에 묶여 있으나 같은 호스트의 다른 프로세스는 접근할 수 있습니다.

| 경계 | 구현된 통제 | 남은 위험 / 운영 판단 |
| --- | --- | --- |
| 업로드 코드·파일명 → API/스캐너 | 허용 텍스트 확장자·MIME·바이트/파일 수/처리 시간 제한, `noexec` 스냅샷, 요청별 임시 디렉터리. Opengrep·Gitleaks·Checkov를 분리 호출하며 제출 코드를 import·실행하지 않음. `/v1/*` 본문 처리 전 회원 세션 또는 선택적 운영 Bearer 토큰 확인, 보고서 조회에 소유자 필터 적용. | 지원 언어·규칙 밖의 취약점·비밀은 놓칠 수 있음. 검사기 프로세스는 API와 네트워크 네임스페이스를 공유하므로 다운로드 금지 설정은 완전한 egress 차단이 아님. 같은 호스트의 악성 프로세스, 자격 증명 탈취, 속도 제한 부재와 Streamlit 세션 침해가 남은 위험. |
| 신뢰된 로컬/CI Git 이력 → Gitleaks | 이력 검사는 업로드·회원 API와 분리된 CLI/CI 경로만 사용. 전체 SHA와 조상 관계, 얕은 체크아웃 여부와 선택 커밋 수를 먼저 확인하며 역사적 코드를 체크아웃·실행하지 않음. Git·Gitleaks 하위 프로세스에 제한된 환경을 제공하고 비밀 필드를 포함하지 않는 보고 템플릿만 해석. 실패·시간 초과·범위 초과는 완료로 표시하지 않음. 공개 CI 아티팩트는 완료·검증된 발견 건 없는 `main` 결과만 게시. | 신뢰된 체크아웃과 CI 실행 환경의 무결성이 필요함. 선택 범위 밖의 커밋과 Gitleaks 규칙에 맞지 않는 비밀은 놓칠 수 있음. 과거 키를 찾아도 자동 폐기·이력 재작성은 하지 않음. 파일명·커밋 SHA 자체는 민감할 수 있으므로 finding 보고서는 CI 아티팩트로 게시하지 않음. |
| 회원 비밀번호·세션 → PostgreSQL | 버전이 있는 scrypt 해시, 임의 세션 토큰의 SHA-256 digest만 DB 저장, 절대·유휴 만료와 로그아웃 폐기, 계정별 실패 횟수 잠금. 기존 소유자 없는 보고서는 회원에게 보이지 않음. | 서비스별 네트워크 속도 제한과 공개 배포용 보안 통제가 없으므로 로컬 포트 바인딩을 유지해야 함. DB 백업에도 해시와 보고서가 남음. |
| 관리 manifest → 공식 PDF 파일 | SHA-256이 일치하는 manifest 지정 로컬 PDF만 pypdf로 추출. 원본 바이트·페이지 수·원시 페이지 스트림·추출 후 페이지/전체 문자 수에 한도를 두며 자동 탐색, 네트워크 다운로드, OCR, 첨부 실행은 하지 않음. | 압축된 PDF 데이터 파싱에는 CPU/메모리 자원 위험이 남으며 추출 후 문자 수 한도는 파서 내부의 압축 해제 비용을 제한하지 않음. PDF 원본은 컨테이너 밖 CLI 프로세스가 읽음. SHA-256은 동일성 확인이지 무해성·재배포 권리 증명이 아님; publisher/version/license를 사람이 검토해야 함. |
| 잠금 파일의 정확한 좌표 → OSV.dev | 공개 레지스트리 `uv.lock`/`package-lock.json`의 확정 버전만 읽고 고정 HTTPS 호스트에 생태계·패키지명·버전만 전송. 잠금 파일과 소스 원문은 보내지 않음. 응답 크기·개수·시간을 제한하고 미지원·불완전 조회를 경고로 표시. OSV가 반환한 ID만 쓰며 CWE/코드 패턴에서 CVE를 추정하지 않음. CLI `--offline`과 API 설정으로 끌 수 있음. | 자동 조회는 패키지 선택과 버전을 외부 서비스에 공개함. 지원하지 않는 잠금 형식과 비공개 레지스트리 항목은 검사하지 않으며, OSV의 빈 결과는 안전 증명이 아님. |
| 평가 사례·실제 스캔 finding·RAG 질문의 CWE 후보 → MITRE CWE API | 초기 코퍼스는 현재 평가 manifest에서 준비하고, 런타임에는 실제 finding 또는 질문에 명시된/분류 모델이 제안한 CWE ID만 공식 API에 조회. 질문 전문과 코드 원문은 MITRE에 보내지 않음. 응답의 HTTPS 출처·크기·ID를 검사하고 항목별 manifest SHA-256·버전·권리 메타데이터를 로컬에 기록. 검증된 캐시를 재사용하며 실패는 내용 없는 범위 경고로 표시. | 모델이 관련 CWE를 놓치거나 잘못 제안할 수 있고 공식 API가 없으면 새 근거가 부족함. 질문 전문은 MITRE에 보내지 않지만 설정된 모델 제공자에는 전달됨. 원격 문서의 정확성·권리 변경은 통제 밖이며 SHA-256은 동일성 확인이지 내용 검증이 아님. |
| ZIP → 파일시스템 | 절대/상위 경로, 중복 경로, 링크·특수 항목, 암호화·지원 밖 압축을 거절하고 총 추출량을 검증. | 복잡한 입력은 여전히 CPU·디스크 자원을 사용할 수 있으므로 격리와 요청 제한이 필요. |
| secret evidence → 보고서·로그 | 새 스캔은 소스 줄을 보고서로 복사하지 않고 고정된 `redacted_evidence`만 기록. 스냅샷 Gitleaks JSON의 비밀 필드는 정규화 중 버리고, 이력 경로는 비밀 필드가 없는 템플릿만 출력합니다. 역사적 SARIF fingerprint는 엔진·규칙·경로·줄·커밋으로 계산하며 현재 파일의 물리 위치를 주장하지 않습니다. DB 마이그레이션은 과거 저장 행의 증거를 고정 문구로 대체. 구조화 로그·감사는 허용된 이벤트/수치만 수용. | 탐지되지 않은 비밀을 포함한 경로·대상 이름·질문·출처 메타데이터는 여전히 민감할 수 있음. 과거 내보낸 보고서·백업·WAL은 마이그레이션이 회수하지 못함. 로그와 산출물은 공유 전 검토 필요. |
| 질문·수집 문서 → 모델 | 프롬프트 인젝션을 신뢰하지 않는 데이터로 전달하고 모델의 도구 접근을 분리. RAG 답변은 검색 결과 ID 인용을 확인하고 무근거면 중단. | 인용의 존재는 내용의 진실성을 보장하지 않음. `general_answer`는 근거 조회 없는 모델 설명임. |
| 오프라인 RAG 매니페스트·동봉 문서 → 테스트 더블·증거 파일 | 메모리 내 Qdrant와 실제 지식 LangGraph를 실행하되 토큰 해시 임베딩과 결정적 응답 어댑터가 모델 제공자를 대체. 원시 graph state 대신 완료 노드·제한된 검색 메타데이터를 기록하고, 인용된 조각에만 최대 240자 발췌를 두며 Markdown 문자를 이스케이프. `adapter_fault`는 기대 라벨과 독립적으로 가짜 인용을 주입해 그래프의 거부를 검사. | 저장소의 고정 자료와 어댑터가 선택한 경로만 검증함. 프롬프트 인젝션 저항성, 실제 임베딩의 의미 검색 품질, 제공자 답변의 사실성·개인정보 처리를 증명하지 않음. 공유 전 생성 파일의 발췌를 검토해야 함. |
| 관리 지식 manifest·런타임 CWE 문서 → Qdrant | 상대 경로·링크·바이트 한도, 출처 URL·라이선스·날짜·원본 SHA-256 검증 후 같은 바이트로 chunk 생성. 코퍼스 ID를 문서 ID에 반영해 초기 평가 코퍼스와 런타임 CWE 코퍼스를 구분하고, 초기 동기화는 런타임 문서를 삭제하지 않음. 런타임 인덱싱은 검증된 공식 항목에만 적용. | 사용자 제공 출처·라이선스 필드 자체의 진실성은 검증하지 못함. 로컬 파일 교체 경합, 임베딩 제공자로의 공식 CWE 원문 전송, Qdrant 비원자적 부분 갱신과 운영자 백업 관리는 남음. 캐시 게시 직후 인덱싱 전에 프로세스가 종료되면 다음 프로세스가 문서 ID만으로 기존 인덱스를 재사용해 잠시 오래된 본문을 검색할 수 있음. 기존 `ingest-documents`는 미검증 경로로 유지됨. |
| 선택적 실제 제공자 평가·외부 벤치마크 | 실제 RAG 평가는 키가 있어야만 시작하고 제한된 경로·분모·해시·에러코드만 로컬 파일로 남김. 외부 스캐너 평가는 별도 로컬 Git 체크아웃의 리비전·CSV digest를 고정하며 코드 실행/import 없이 읽음. | 실제 모델 답변의 사실성은 자동 측정하지 않음. 외부 자료의 라이선스·진위와 광범위한 CWE→규칙 매핑의 미지원 sink는 사용자 검토 대상. 두 결과는 기본 CI 아티팩트가 아님. |
| 모델 출력 → 스캔/지식 결과 | 스캔 finding과 수정 권고는 결정적이며 모델 출력으로 변경하지 않음. 지식 그래프는 답변 크기·제어 문자·인용 ID를 검사. | 자연어 답변은 여전히 부정확하거나 악성 문서의 영향을 받을 수 있어 중요한 판단에는 원문 확인 필요. |
| 생성 SQL → PostgreSQL | SQLGlot AST의 단일 `SELECT`, `intel.cwe`/`intel.cve` 허용 목록, `LIMIT`, 전용 읽기 전용 로그인, `SET TRANSACTION READ ONLY`, `statement_timeout`, 제한된 재시도. | 허용된 읽기 쿼리도 자원을 소모하거나 부정확한 집계를 만들 수 있음. 실제 데이터 권리·품질은 별도 확인. |
| 보고서 DB·문서 DB | `app`과 `intel` 스키마를 분리하고 reader의 `app` 접근을 제거. Qdrant 컬렉션 차원/거리 확인. 영속 볼륨은 Compose 종료 후에도 남음. | 로컬 PostgreSQL/Qdrant 포트는 루프백에 열림. 백업·볼륨·호스트 접근 통제는 운영자 책임. |
| 로그·감사·CI 토큰 | UUID 상관 ID, 내용 없는 허용 목록 감사 이벤트; CI는 기본 `contents: read`, SARIF 업로드 job에만 `security-events: write`, fork/Dependabot PR의 업로드 제외. 키 없는 RAG/스캐너 증거 아티팩트는 신뢰된 `main` push에서만 게시. | CI 성공과 게시 여부는 해당 커밋의 실행으로 확인해야 함. 합성 자료의 짧은 인용 발췌가 들어간 아티팩트도 공개 전 검토해야 함. |
| 클라우드 제공자 자격 증명 | `SECRAGRAPH_OPENAI_API_KEY`는 선택적 런타임 환경 값이며 이미지/예제에 넣지 않음. 컨테이너는 비루트·읽기 전용 루트 파일시스템으로 실행. | 제공자 호출에는 질문 또는 인덱싱할 문서 텍스트와 finding 검색어가 서비스 밖으로 전달됨. 민감 자료는 제공자 정책을 확인한 뒤에만 사용. |

오프라인 증거 명령은 실제 제공자 어댑터를 호출하지 않으며, 키·네트워크·PostgreSQL·Docker 없이 동작합니다. 반면 API의 실사용 경로는 설정된 임베딩·채팅 제공자와 Qdrant 컬렉션을 사용합니다. 테스트 더블에서 정상 인용을 만들었다는 사실은 외부 제공자 응답의 안전성이나 답변 품질로 이전되지 않습니다. 평가 JSON의 `corpus_sha256`은 `indexed-chunks-v1` 형식으로 인덱싱된 chunk 레코드의 digest이며 원본 지침 파일 바이트의 해시가 아닙니다. 지식 manifest의 문서별 `sha256`은 별도로 **원본 Markdown 바이트**를 확인합니다. 매니페스트의 예상 결과가 바뀌어도 응답 어댑터의 정상 동작은 그 라벨을 읽어 정답을 만들지 않습니다.

런타임 CWE 경로는 스캔당 64개, 질문당 8개의 후보 ID를 다루고 응답 총 8 MB, 동시 조회 4개, 최대 12초와 임시 캐시 16 MB·인덱스 문서 1,024건으로 제한합니다. 이 수치는 고정 평가 사례 수와 무관한 자원 상한입니다. 제한이나 외부 장애로 일부 근거를 못 얻으면 기존 finding을 보존하고 불완전 범위를 경고합니다. CWE 자료가 있는 경우에도 실제 취약성·악용 가능성이나 CVE 일치를 보증하지 않습니다.

## 경계 간 실패 처리

정적 스캔은 모델 없이도 실행됩니다. Qdrant/임베딩 실패는 이미 확인한 finding을 지우지 않고 경고와 함께 부분 보고서로 남길 수 있습니다. API 보고서 영속화를 위한 PostgreSQL 장애는 별도로 다루며 readiness가 실패합니다. 지식 API는 필요한 제공자·데이터가 없으면 503 또는 근거 부족 답변을 반환합니다. 생성 SQL 거절은 데이터베이스 조회로 넘어가지 않습니다.

업로드 제한, 비밀번호 회전, 볼륨 보존/삭제 절차는 [운영 문서](operations.md)에 있습니다. 취약점 제보는 [보안 정책](../SECURITY.md)을 따릅니다.
