# CI Rescan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-run the existing nine security and quality jobs weekly or on demand against trusted `main`, with correct history and image baselines and validated artifacts.

**Architecture:** Reuse the two existing workflows and their job names. Extend the event-specific history selector to a pinned post-baseline range and use the event commit as the image baseline for scheduled or manual rechecks.

**Tech Stack:** GitHub Actions YAML, Python 3.11, pytest, Git, Gitleaks, Trivy.

**Spec:** [CI 재검사 설계](../../design/ci-rescan.md).

## Global Constraints

- Preserve all nine existing GitHub Actions job names and PR/push behavior.
- Scheduled history base is `313a2adc3968a37a1ce63d41a3d7531468a93d00`; never add a secret allowlist.
- Publish only normalized, successful evidence from trusted `main` events.

## Review Focus

- Manual run on a feature branch must not publish evidence; history selection fails.
- Missing or unrelated baseline commit must fail before scanning.
- Checkout HEAD differing from `GITHUB_SHA` must fail before scanning.
- A new dependency advisory or image finding must remain blocking on a scheduled run.
- A malformed event type must remain unsupported.
