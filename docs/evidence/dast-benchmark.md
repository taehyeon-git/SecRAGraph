전체 F1은 **0.857**이다. 패시브 실행 15,360 ms, 능동 실행 19,811 ms, 준비·검사·정리를 포함한 측정 구간은 53,936 ms였다. 개별 규칙 시간은 같은 ZAP 실행을 공유하므로 산출하지 않았다. 평가 대상 외의 정규화된 경고는 15건이고, 탐지된 사례의 CWE 메타데이터 불일치는 0건이다. 15건은 원시 ZAP의 전체 경고 수가 아니다.

## 2026-10-31 별도 차등 엔진 실측

같은 8개 취약·정상 경로와 라벨을 유지하면서 숫자형 2개 사례의 채점 규칙을 `ZAP/40018`에서 `DIFF/NUMERIC_SQLI`로 변경했다. 따라서 **전체 분모는 양성 4·음성 4로 동일**하지만 규칙별 분모와 manifest 해시는 달라졌다. `ZAP/40018`은 문자열형 2개 사례만 채점한다. 숫자형 발견에는 `engine=dast-differential`을 기록하고, ZAP 자체에는 여전히 숫자형 `40018` 경고가 없다.

| 규칙 · 분류 | TP | FP | FN | TN | 정밀도 | 재현율 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `ZAP/10021` 보안 헤더 | 1 | 0 | 0 | 1 | 1.000 | 1.000 |
| `ZAP/20019` 외부 리디렉션 | 1 | 0 | 0 | 1 | 1.000 | 1.000 |
| `ZAP/40018` 문자열 SQL 주입 | 1 | 0 | 0 | 1 | 1.000 | 1.000 |
| `DIFF/NUMERIC_SQLI` 숫자형 SQL 주입 | 1 | 0 | 0 | 1 | 1.000 | 1.000 |

차등 검사는 추가 허용 라벨이 붙은 전체 64자리 컨테이너 ID와 격리 Docker 네트워크 안에서만 실행한다. 정제된 OpenAPI의 표시된 GET 시작 경로에서 경로 항목의 파라미터 상속과 GET의 재정의를 해석한 뒤, 숫자 예제가 있는 query 파라미터를 최대 16개 선택한다. 함께 제공해야 할 다른 필수 파라미터가 있으면 해당 경로를 건너뛴다. 각 경로에 baseline, 동등성 대조(`1+0`), 참(`1 OR 1=1`), 거짓(`1 OR 1=2`)을 2회씩 요청해 상태와 최대 4 KiB 정규화 응답 본문의 일회용 키 기반 HMAC-SHA-256을 비교한다. 최대 16개 경로의 결과 출력은 64 KiB로 제한한다. baseline·대조·거짓이 모두 같은 200 응답이고 참만 안정적으로 다를 때 발견을 낸다. 보고서에는 관계를 검증할 수 있는 짧은 HMAC 접두부만 기록하고 키는 보관하지 않는다. baseline이 200이 아니거나 어느 변형에서든 401·403·404·429, 리디렉션, 서버 오류, 과대 응답, 시간 초과 또는 반복 불일치가 있으면 `partial`로 처리하고 채점을 거부한다. 정상 경로가 주입 문자열에 422를 반환하는 경우는 완결된 음성 대조로 인정한다. 적격 숫자 seed가 없으면 별도 실행은 `skipped`로 기록된다. 응답 본문·요청 값·토큰은 보고서에 보관하지 않는다.

최종 코드의 로컬 Docker 실측에서 숫자형 취약 경로는 TP, 정상 대조 경로는 TN이었다. 차등 엔진은 2개 seed에 추가 요청 **16회**를 사용했고 **827 ms**가 걸렸다. ZAP 패시브 **15,655 ms**, ZAP 능동 **31,875 ms**, 준비·검사·정리 포함 전체 **100,625 ms**였다. 추가 요청이 포함된 공격형 증거 계수는 숫자형 두 경로 각각 69였다. 평가 대상 외 정규화 finding은 15건, CWE 불일치는 0건이다. 실측 재현 신원은 새 manifest SHA-256 `5ebdae87db7af9c06637beb7d6ef581853445b633901a3b1e792b317323cc2b7`, 소스 리비전 `3b50e6eeac619d316d49f82ad11ad12625df9c21` (`source_dirty=true`), 테스트 이미지 `sha256:a6d524b1de04bb0adb9338580e5dab9d03b193308be53123488385e7f4e95bb2`다. 작업트리에 미커밋 변경이 있으므로 이 이미지 ID는 추후 빌드에서 바뀔 수 있다.

## 해석 범위

- 취약·정상 라벨은 테스트 API의 HTTP 동작으로 확인했고 ZAP 경고에서 역산하지 않았다. 작성자 사례 8개만으로 실사용 정밀도나 재현율을 주장하지 않는다.
- 능동 검사는 추가 허용 라벨이 있는 일회용 컨테이너의 표시된 GET 시작 경로에서만 시작한다. 시작 경로는 모든 실제 요청의 허용 목록이 아니며, 같은 출처의 미등록 경로 경고는 보고서에 남지 않는다. [ZAP API Scan](https://www.zaproxy.org/docs/docker/api-scan/)은 OpenAPI를 가져와 능동 검사를 실행한다.
- 로컬 Windows 실행에서는 Linux 전용 호스트 게이트웨이 마커 시험을 건너뛰었다. Linux CI의 별도 DAST 작업이 네트워크 격리를 검증한다. 이미지 ID와 시간은 빌드·실행 환경에 따라 달라질 수 있다.
- 차등 검사는 숫자 예제가 있고 다른 필수 입력 없이 요청할 수 있는 문자 그대로의 GET 경로만 대상으로 한다. 정상 응답이 입력 값에 따라 달라지는 API나 비결정적 응답은 이 규칙의 탐지 범위 밖이다. 추가 규칙·HTTP 메서드·인증 흐름·다양한 운영 API는 이 벤치마크의 분모에 없다. `ZAP/40018`의 탐지 방식은 [ZAP 공식 규칙 설명](https://www.zaproxy.org/docs/desktop/addons/active-scan-rules/)을 참고한다.
